## 微信cron推送排障（深度排查）

### 问题
用户反馈今日3条早间推送（AI HOT 06:50 / AI日报 07:30 / AI Builders 08:00）全部未收到。cron状态显示 `status=ok, delivered=True`。

### 排查过程
1. 确认3个任务cron state全部 `delivered=true, consecutiveErrors=0` — 系统认为成功
2. 读openclaw-weixin插件源码，发现核心问题：
   - `sendMessage()` 返回 `Promise<void>`，微信API返回的rawText被完全丢弃
   - `SendMessageResp` 类型定义为空 `interface { // empty }`
   - 唯一的debug日志 `logger.debug(...)` 被默认INFO级别过滤
   - `messageId` 返回的是本地生成的clientId，不是微信的ID
3. 在 `api.ts` 的 `apiPostFetch` 中给 `label === "sendMessage"` 加了INFO级别排障日志
4. 重启gateway后手动触发3个cron任务
5. 日志确认微信API返回：`httpStatus=200 resp={"message_id":7487336687196277896}`
6. 手动触发 → 用户微信端全部收到
7. 定时触发 → 用户微信端全部收不到

### 关键结论
- **微信API返回结构**：HTTP 200 + `{"message_id": xxx}`，无ret/errcode/errmsg字段
- **API层无法判断投递是否真正成功** — 微信只确认"收到请求"，不确认"送达用户"
- **手动触发能收到、定时触发收不到** → 问题在微信端频率限流，不在API层
- 与MEMORY.md教训#16一致：早间6条消息在110分钟内集中投递触发限流
- 用户决定暂不调整推送时间

### 改动
- `/root/.openclaw/extensions/openclaw-weixin/src/api/api.ts`：sendMessage添加INFO级别排障日志
- 排障日志持续开着，明天cron正常执行后可再次对照

### 教训更新
- cron的 `delivered=true` 含义 = "HTTP 200收到" ≠ "用户微信可见"
- 微信API不提供投递回执，无法从API层判断真实送达状态
- 手动触发vs定时触发的差异 = 频率限流（非API差异）

## cron投递方案反转（announce → message工具）

### 背景
07-21定案的 `delivery.mode=announce` 方案，在07-27再次出现"cron显示delivered但用户收不到"的问题。

### 根因
- announce投递走OpenClaw框架层，调用 `outbound.sendText`
- 微信API只返回 `{"message_id": xxx}`，无投递回执
- 06:50-08:00三个任务密集执行时，微信端疑似频率限流，消息静默丢弃
- announce模式下OpenClaw无法感知限流，仍标记delivered=true

### 新方案（07-27验证通过）
**delivery.mode = none/off + prompt中让AI用message工具主动发送**

关键配置：
1. `delivery.mode = none`（关闭系统层announce投递）
2. prompt中明确写message工具调用方式，**必须带to参数**：
   ```
   message(action="send", channel="openclaw-weixin", to="o9cq80_r2wmTBUtFu0AJ6T-jxK68@im.wechat", message="<内容>")
   ```
3. isolated session没有"当前用户"上下文，不带to会报 `Action send requires a target`

### 验证结果
- 手动触发3个任务，全部成功投递，用户确认收到
- message工具走的是channel层发送（同主会话路径），不是announce框架层
- 微信API返回一致：`httpStatus=200 resp={"message_id":xxx}`

### 为什么这次能成功而announce不行？
两种方案最终都调 `sendMessageWeixin()` → HTTP POST到微信API。差异在于：
- **announce路径**：cron框架 → outbound.sendText → sendMessageWeixin（可能被框架层限流/排队）
- **message工具路径**：AI调message工具 → channel.sendText → sendMessageWeixin（直接走channel发送，与主会话消息同路径）
- message工具路径多了contextToken（会话上下文），微信端可能因此不会被限流

| 每日AI热点推送 | none | message工具 + to参数 |
