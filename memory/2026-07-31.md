
## 微信推送 tokenless 降级方案（11:00-12:00）

### 问题根因
- context_token 24小时过期（官方文档确认）
- 过期后所有 cron 推送 ret=-2 "prepare failed"
- 插件原代码不检查 ret 值，HTTP 200 就当成功 → delivered=True 但实际未发送

### 调研发现
- GitHub 上 hermes-agent #56814/#35949/#35062 多个项目遇到同样问题
- 实测 tokenless 发送（不带 context_token）可以成功投递
- getconfig API 不能刷新 context_token（不返回该字段）

### 代码修改（2个文件）
1. **api.ts** `apiPostFetch()`: 加 ret≠0 业务错误码检查，throw 带 ret/errmsg 的 Error
2. **send.ts**: 新增 `sendWithFallback()` 函数
   - Phase 1: 带 context_token 发送
   - Phase 2: 业务错误 → 降级 tokenless 重试（2次，间隔1s）
   - sendMessageWeixin + sendMediaItems 都走 sendWithFallback
3. 第一版（固定重试3次同token）已废弃

### 备份
- api.ts.bak / send.ts.bak 在原目录
